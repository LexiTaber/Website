Rebuilding an eligibility and lending pipeline

Replaced a spreadsheet-driven review with a structured data model and automated decision support, so a small team could screen more deals with fewer errors.

01 · THE PROBLEM

Rules lived in spreadsheets and inboxes

Every eligibility review meant re-keying data into a template and checking it by hand. The rules changed faster than anyone could update the templates, so two reviewers could reach two different answers on the same deal.

02 · CONSTRAINTS

Small team, changing rules, audit trail required

  • No budget for a managed package
  • Program staff, not developers, own the rules and need to change them
  • Every decision has to be explainable after the fact

03 · DECISIONS I OWNED

Rules as records, not code

Modeled each eligibility criterion as data so program staff can update thresholds without a deployment.

Flow where staff maintain it, Apex where it has to scale

Kept staff-owned steps in Flow and moved bulk calculations and validation into tested Apex.

A review screen that shows its work

Built an LWC that shows each criterion's result and the data behind it, so reviewers can trust the answer.

Build it and coach it

Wrote the Apex myself while pairing with a teammate on the Flow layer, so the team can own it after launch.
